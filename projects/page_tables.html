Page Tables and Replacement Algorithms

Implementing three-level page table address translation and four page replacement algorithms — FIFO, LRU, CLOCK, and ARC — from scratch.

October – November 2022 C · Operating Systems · Memory Management

Overview

Many students learn about page tables, address translation, and page replacement algorithms in theory. In this project, I got the opportunity to implement those ideas in practice.

There were two parts to the project:

  • Multilevel page tables — translating virtual addresses into physical addresses through a three-level page table, using bitwise operations.
  • Replacement algorithms — implementing four different page replacement policies and comparing them against each other.

Part 1: Page Tables and Address Translation

In this task, we are given virtual addresses and need to translate them into physical addresses using a three-level page table. The translation is done through bit manipulation: different portions of the virtual address are extracted and used as indices into each level of the page table.

Given a virtual address, some of the bits serve as an index into the first-level page table, some as an index into the second-level page table, some as an index into the third-level page table, and the remaining bits specify the offset within the page.

The lookup proceeds level by level. Indexing into the first-level page table returns a pointer to a second-level page table. Indexing into that returns a pointer to a third-level page table. Finally, indexing into the third-level page table with the remaining bits retrieves the physical page frame, which is combined with the offset to produce the physical address.

Getting this right required careful attention to bit layout: how many bits belong to each level, how they're shifted and masked, and how the offset is preserved. A single mistake in the shifting would produce an address that pointed somewhere entirely wrong.

Part 2: Replacement Algorithms

In the second task, I implemented four different page replacement algorithms: FIFO, LRU, CLOCK, and ARC. Since page replacement happens on every memory access, these policies need to be fast, so I implemented each one with efficiency in mind.

The idea behind replacement algorithms is straightforward: as pages are requested, memory fills up. Once memory is full and a new page is requested, the algorithm has to decide which existing page to evict to make room.

  • FIFO (First In, First Out) — evicts the oldest page in the cache.
  • LRU (Least Recently Used) — tracks recently used pages and evicts the one that has not been used for the longest time.
  • CLOCK — a low-overhead approximation of LRU. Instead of tracking the least recently used page precisely, it uses reference bits to find a page that is "old enough" to evict.
  • ARC (Adaptive Replacement Cache) — an advanced algorithm that tracks both recently used pages and frequently used pages, plus a recent history of evictions. It is self-tuning, low-overhead, scan-resistant, and responsive to changing patterns in memory access.

Comparison Report

At the end of the project, I wrote a report comparing the four replacement algorithms against each other. Rather than just listing theoretical differences, I constructed memory access traces where one algorithm outperformed the others, and used those traces to demonstrate the practical consequences of each policy.

This was one of the most interesting parts of the project: it made the trade-offs concrete. Two algorithms that look similar on paper can behave very differently on a specific workload, and seeing that play out on traces I designed myself made the theory much more tangible.

Reflections

This project turned abstract operating systems concepts into something I had to reason about concretely. Page tables, bit-level address translation, and replacement policies are all things that are easy to describe in a lecture but tricky to get right in code — especially when correctness depends on exact bit manipulation and exact bookkeeping.

It also gave me a deeper appreciation for why operating systems care so much about the cost of these operations. A page replacement algorithm runs on every memory miss, so a small inefficiency compounds quickly. Writing these policies myself made the design trade-offs feel less like trivia and more like engineering decisions with real consequences.
