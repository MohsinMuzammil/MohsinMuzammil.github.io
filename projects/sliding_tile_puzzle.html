Sliding Tile Puzzle

A solver for the classic sliding tile puzzle, implementing both DFS and A* search with an admissible Manhattan distance heuristic.

September 2024 Python · Artificial Intelligence · State Space Search

Overview

In this project, I developed a solver for a sliding tile puzzle inspired by Hua Rong Dao. The goal is to navigate a board of movable pieces into a specified goal configuration using as few moves as possible.

I implemented two search algorithms to compare their behavior: Depth-First Search (DFS) and A* search. DFS served as a baseline for exploring the state space, while A* with an admissible heuristic was responsible for finding optimal solutions efficiently.

The A* Heuristic

One of the highlights of the implementation was the design of the heuristic function for A*. I used the Manhattan distance: for each piece on the board, I computed the number of horizontal and vertical steps required to move it to its goal position, and summed those distances across all pieces.

Manhattan distance is admissible — it never overestimates the true cost of reaching the goal — which guarantees that A* finds an optimal solution. It's also far more informative than a naive heuristic like counting misplaced tiles, which allowed the search to reach the goal in significantly fewer expansions.

Successor Generation

I also took care in writing a clean, modular function for generating successor states. Movement directions are encoded as a simple list:

  • (0, 1) — right
  • (0, -1) — left
  • (1, 0) — down
  • (-1, 0) — up

By iterating over this list and checking each candidate move against the board's dimensions, the successor function stays compact while still handling every piece correctly. The result is code that's easy to reason about and easy to extend if the puzzle format changes.

Handling Puzzles of Varying Complexity

The solver was designed to handle puzzles across a range of difficulties, from simple configurations solvable in a few moves to genuinely challenging boards. Each stage of the pipeline — parsing the input files, running the search, reconstructing the solution path via backtracking — was tested and refined separately to keep the overall system dependable.

Results

Seconds solves complex puzzles while keeping the code clean and modular

The final program solves even complex puzzles in seconds using A*, while DFS provides a useful baseline for comparison.

Reflections

This project deepened my understanding of state-space search algorithms — not just how DFS and A* work in theory, but why their performance differs so dramatically in practice. The choice of heuristic, in particular, turned out to be the single biggest factor in whether a puzzle was solved in a few seconds or took minutes.

It also honed my skills in writing modular, efficient Python code. Keeping each piece of the pipeline — parsing, search, reconstruction — separate and testable made the project far easier to debug and extend than it would have been as a single monolithic script.
