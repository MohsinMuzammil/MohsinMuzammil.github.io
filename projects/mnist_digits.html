Handwritten Digit Classification

Implementing a k-Nearest Neighbors classifier from scratch to recognize handwritten digits from the MNIST dataset.

January 2025 Python · Machine Learning

Overview

In this project, I implemented a k-Nearest Neighbors (k-NN) classifier from scratch to classify handwritten digits from the MNIST dataset. The goal was not simply to train a model, but to understand the algorithm at the level of matrices, vectors, and distance computations—and to see how far careful implementation and preprocessing could take a classical method.

The workflow began with storing the dataset in matrices and vectors, then splitting it into training, validation, and test sets. From there, I built the core k-NN machinery by hand, tuned it, and evaluated its ability to generalize to unseen data.

Implementation

The heart of the classifier is the distance computation: given a test image, I needed to compute its squared Euclidean distance to every training image. A naive implementation would use nested loops, but that scales poorly and misses the point of working with NumPy.

Instead, I implemented the distance computation using vectorization and broadcasting, so that the entire set of pairwise distances could be computed in a single array operation. Using np.argsort() for distance sorting, the full k-NN algorithm became compact, readable, and performant—without any explicit Python loops over individual images.

This was one of the most valuable parts of the project: it forced me to think about how array shapes align, how broadcasting rules work, and how to express an algorithm in the language of linear algebra rather than in loops.

Tuning k

With the classifier working, I evaluated its accuracy across different values of k, from 1 to 10, using the validation set. The initial results were disappointing: accuracy hovered around 30%, barely better than chance on a 10-class problem.

Something was clearly wrong, and the issue turned out not to be the algorithm but the data. Raw pixel values vary widely in scale, and without normalization, the distance metric was being dominated by whichever pixels happened to have the largest values.

Normalization

To address this, I normalized the dataset by subtracting the mean and dividing by the standard deviation of the training data. Crucially, the statistics were computed only from the training set and then applied consistently to the validation and test sets—avoiding any information leakage from the held-out data.

This single preprocessing step boosted validation accuracy from roughly 30% to over 90%. It was a striking reminder that in machine learning, how you prepare the data often matters as much as the model itself.

Results

90%+ accuracy on the test set with the optimal k

Using the optimal k value identified during validation, I applied the classifier to the test set and achieved over 90% accuracy. This confirmed that the model generalized well to data it had never seen—and that the normalization step had genuinely improved the classifier's decision boundary rather than just its performance on the validation split.

Reflections

This project was an exercise in doing more with less. k-NN is one of the simplest classifiers in machine learning, but implementing it from scratch—and getting it to work well—required careful thinking about vectorization, numerical scale, and evaluation.

It strengthened my intuition for NumPy broadcasting, for preprocessing as a first-class part of the pipeline, and for the importance of computing statistics only from training data. It was also a good reminder that performance problems are not always algorithmic: sometimes the fix is a single line of normalization.
